# 쇼핑검색광고 실적 대시보드

네이버 쇼핑검색광고 실적을 조회하고 전년 대비 비교하는 Streamlit 대시보드입니다.

## 현재 범위

지금은 **② 일일리포트[태블로]** 기준 실적(01·02 페이지)만 운영합니다.
① 쇼핑검색광고 리포트(NBOS 매칭) 기준의 카테고리별/브랜드별 실적, 핏플랍 제외 비교,
EP 상관관계 분석은 일단 제외했고, 필요해지면 다시 추가합니다.
(관련 로직은 `utils.py`에 그대로 남아 있어 재활성화가 쉽습니다 — `git log` 또는 이전 버전 참고)

## 구성

```
shopping-ad-dashboard/
├── app.py              # 메인 대시보드 (01. 쇼핑검색광고 실적 / 02. 전년비교)
├── utils.py             # 데이터 로드 + 비율지표 재계산 + 기간/비교 로직
├── styles.py            # 다크 사이드바 + KPI 카드 + 배지 스타일 컴포넌트
├── converter_app.py     # 원본 리포트 → 대시보드용 CSV 변환기 (별도 실행)
├── data/
│   └── tableau_daily.csv   # ② 일일리포트[태블로] 일자별 실적 (01·02 페이지 기준)
├── requirements.txt
└── README.md
```

## 대시보드 페이지

1. **쇼핑검색광고 실적** — 기준일자(일/주/월 단위 선택) + 표시방식(누계/일평균), KPI 카드
   (전일·전주·전월비 + 전년비 배지, 비교대상 기간 항상 명시), 실적요약 비교 테이블,
   2026년 추이(전년비 비교선) 차트, 원본 데이터 다운로드
2. **전년비교** — 일자별 YoY(전년 동일 요일 매칭, 임의 날짜 범위 선택 가능) /
   월별 누적 YoY(임의의 두 연도 비교 가능)

## 전년비 비교 기준

- **일별/주별/월별**: 전년 **동요일비** — 364일(52주) 전, 요일이 정렬된 날짜와 비교
- **월마감**: **정확히 12개월 전 같은 달**(마감 실적 기준)로 비교 — 월 경계에서 요일 시프트로 인해
  다른 달이 걸리는 일이 없도록, 월마감만 예외적으로 달력월 그대로 비교합니다

어느 경우든 카드/차트에 실제 비교대상 기간(날짜 범위)이 항상 캡션으로 표시됩니다.

## 비율 지표 처리 원칙

CTR, CR, 객단가, ROAS, 순결제비중 등 비율 지표는 절대 **일자별 값의 평균을 내지 않습니다.**
대신 `utils.py`의 `RATIO_DEFS`에 정의된 분자/분모 원천값(base metric)을 먼저 합산한 뒤
재계산하여, 어떤 기간으로 집계하든 정확한 값이 나오도록 했습니다.


## 데이터 갱신 (고정 구간 + 증분 업데이트)

일일리포트[태블로] 데이터 중 **특정 날짜까지는 확정(고정)** 되어 값이 바뀌지 않는다면,
그 이후 새로 채워지는 날짜만 계속 업데이트하면 됩니다. `converter_app.py`가 이 워크플로를 지원합니다:

```bash
streamlit run converter_app.py
```

**① 일일리포트[태블로] 탭**에서:
1. 새로 받은 원본 엑셀을 업로드
2. (선택) 기존 `tableau_daily.csv`를 같이 업로드
3. 🔒 고정 기준일을 지정 (예: 2026-07-31)
4. → 고정 기준일 **이전**은 기존 파일 값을 그대로 유지하고, **이후**만 새 원본 값으로 채우거나
   덮어쓴 병합 결과가 나옵니다

기존 파일을 올리지 않으면 예전처럼 원본 전체를 새로 변환합니다 (최초 1회 또는 전체 재검증이
필요할 때 사용).

**② 카테고리별 실적 탭**은 `네이버_쇼검_ep거래액_상세_YYYYMMDD.csv` → `category_daily.csv` 변환용으로
남겨뒀습니다 (현재 대시보드에서는 미사용, 추후 재활성화 대비).

변환 후 행 수·날짜 범위·날짜 누락 여부를 바로 확인할 수 있고, 다운로드한 파일로 GitHub 리포의
`data/tableau_daily.csv`를 교체(덮어쓰기)하면 됩니다.
